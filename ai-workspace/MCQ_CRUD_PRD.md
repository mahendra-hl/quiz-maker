# MCQ Create, Update, Delete, and Preview - Technical PRD

## Overview/Problem

Teachers can register, log in, and land on `/test-bank`, but that page is still a stub. They cannot author a shared multiple-choice question, list what is already in the bank, edit or remove a question, or try a question and see whether the chosen option is correct. This phase replaces the stub with a question table and a create/edit page, and it records each preview attempt against a specific question and choice.

---

## Hypothesis

We believe that a shared MCQ table with create, edit, delete, and preview — backed by D1 tables for questions, choices, and attempts — will let teachers build and check multiple-choice questions in the quiz maker without adding quizzes, students, or sessions.

---

## Scope

### In Scope

- D1 migration for three tables: `questions`, `choices`, and `attempts`
- Question service that creates, lists, reads, updates, and deletes questions together with their choices
- Attempt service that records which choice a user submitted and whether it was correct
- HTTP APIs to list, create, update, delete, and preview questions
- HTTP APIs to create an attempt and list attempts for a question
- `/test-bank` becomes the question list: shadcn table, Create button, and a three-dot row menu
- A dedicated create/edit page with Save and Cancel
- A preview page where the teacher selects one choice, submits, and sees a correct or incorrect message
- Default two choice fields on the form; the teacher may add choices up to six
- Exactly one choice marked correct per question
- Strict TDD: behaviour tests written first (red), then implementation (green)
- Existing login, logout, and in-memory current-user behaviour stay as they are

### Out of Scope

- Quizzes, assignments, timed tests, or scoring dashboards
- Student accounts or a separate student-facing app
- Question ownership, sharing rules, comments, or concurrent editing
- Images, rich text, or media attachments on questions or choices
- Multiple correct answers, “select all that apply”, or partial credit
- Cookies, sessions, JWT, or route middleware that re-checks identity
- Pagination, search, sort, or tags on the test-bank table
- Editing or deleting an attempt after it is recorded

### Cut

- **Per-teacher question ownership** — The last sprint treated `/test-bank` as a shared bank. Adding `created_by` now would invent an ownership model the product has not defined.
- **Revealing the correct choice after a wrong answer** — Preview only tells the teacher whether the selected option is correct or incorrect. Showing the right label is a later teaching aid.
- **react-hook-form / a client state library** — Auth forms already use shadcn `field` plus `fetch`. Keep that pattern.
- **Server-side auth on these APIs** — There is still no session. Do not add cookies to “protect” MCQ routes in this phase.

## Technical Requirements

### Database Schema

D1 is already bound as `DB` (`quiz-maker-db`) from the registration/login sprint. Add a new Wrangler migration. Do not change the schema with ad-hoc SQL. Do not apply migrations remotely.

```sql
CREATE TABLE questions (
  id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
  name TEXT NOT NULL,
  question TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE choices (
  id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
  question_id TEXT NOT NULL,
  label TEXT NOT NULL,
  is_correct INTEGER NOT NULL DEFAULT 0,
  position INTEGER NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (question_id) REFERENCES questions(id) ON DELETE CASCADE
);

CREATE INDEX idx_choices_question_id ON choices(question_id);

CREATE TABLE attempts (
  id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
  question_id TEXT NOT NULL,
  choice_id TEXT NOT NULL,
  user_id TEXT,
  is_correct INTEGER NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (question_id) REFERENCES questions(id) ON DELETE CASCADE,
  FOREIGN KEY (choice_id) REFERENCES choices(id) ON DELETE CASCADE,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);

CREATE INDEX idx_attempts_question_id ON attempts(question_id);
CREATE INDEX idx_attempts_user_id ON attempts(user_id);
```

Column rules:

- `questions.id` — opaque text primary key generated by SQLite
- `questions.name` — required, trimmed, non-empty; short title shown in the table
- `questions.question` — required, trimmed, non-empty; the stem shown to the person answering
- `choices.question_id` — required foreign key to `questions.id`
- `choices.label` — required, trimmed, non-empty; the option text
- `choices.is_correct` — `0` or `1`. Exactly one choice per question must be `1`
- `choices.position` — `1` through `6`, unique per question, display order
- A question must have at least 2 and at most 6 choices
- `attempts.question_id` — the question that was answered
- `attempts.choice_id` — the choice the user selected
- `attempts.is_correct` — snapshot at submit time (`1` if that choice’s `is_correct` was `1`)
- `attempts.user_id` — optional; the client-held teacher id from the last sprint when present
- Deleting a question deletes its choices and attempts (`ON DELETE CASCADE`)

SQLite stores booleans as integers. The service layer exposes them as `boolean` in TypeScript.

### Service layer

Centralize D1 access in `src/lib/services/`. Route handlers must not run SQL. Use prepared statements with numbered placeholders (`?1`, `?2`). Prefer `results[0]` over `first()`. Validate all service input with Zod.

#### Question service (`src/lib/services/question.ts`)

- `listQuestions()` — all questions, newest `created_at` first, without choices
- `getQuestionById(id)` — question plus choices ordered by `position` (includes `isCorrect`)
- `createQuestion({ name, question, choices })` — insert question and choices in one operation
- `updateQuestion(id, { name, question, choices })` — replace name, stem, and the full choice set
- `deleteQuestion(id)` — delete the question (choices and attempts cascade)

`choices` on create/update is an array of `{ label, isCorrect, position? }`. The service assigns `position` 1..n from array order if omitted.

Create/update validation:

- `name` and `question` trimmed and non-empty, max 200 and 2000 characters respectively
- 2–6 choices
- every `label` trimmed and non-empty, max 500 characters
- exactly one `isCorrect: true`
- unknown `id` on update/delete → not-found error

#### Attempt service (`src/lib/services/attempt.ts`)

- `createAttempt({ questionId, choiceId, userId? })` — load the choice, confirm it belongs to the question, persist `is_correct` from that choice, return the attempt
- `listAttemptsByQuestionId(questionId)` — attempts for that question, newest first

Create validation:

- `questionId` and `choiceId` required
- choice must belong to that question; otherwise validation/not-found error
- `userId` optional; when present it must be a non-empty string
- Do not trust a client-supplied `isCorrect`; always derive it from the stored choice

### API Endpoints

Next.js App Router route handlers under `src/app/api/`. Validate every body and id with Zod before use. No endpoint may set or read cookies. List/get-for-edit responses include `isCorrect` on choices so the authoring form can be edited. The preview response must **not** include `isCorrect`.

Public shapes:

```json
{
  "question": {
    "id": "…",
    "name": "Cell membrane",
    "question": "What is the main function of the cell membrane?",
    "createdAt": "…",
    "updatedAt": "…",
    "choices": [
      { "id": "…", "label": "Control what enters and leaves the cell", "isCorrect": true, "position": 1 },
      { "id": "…", "label": "Store genetic material", "isCorrect": false, "position": 2 }
    ]
  }
}
```

List items omit `choices`.

#### GET /api/questions

Lists questions for the test-bank table.

**Response:**

- Success (200): `{ "questions": [ { "id", "name", "question", "createdAt", "updatedAt" } ] }`
- Error (500): unexpected server error

#### POST /api/questions

Creates a question and its choices.

**Request Body:**

```json
{
  "name": "Cell membrane",
  "question": "What is the main function of the cell membrane?",
  "choices": [
    { "label": "Control what enters and leaves the cell", "isCorrect": true },
    { "label": "Store genetic material", "isCorrect": false }
  ]
}
```

**Response:**

- Success (201): `{ "question": … }` including choices with ids and `isCorrect`
- Error (400): validation failure (blank name/stem, fewer than 2 or more than 6 choices, blank label, not exactly one correct choice)
- Error (500): unexpected server error

#### GET /api/questions/[id]

Returns one question with choices for the edit form.

**Response:**

- Success (200): `{ "question": … }`
- Error (404): `"Question not found."`
- Error (500): unexpected server error

#### PUT /api/questions/[id]

Replaces name, stem, and the full choice set.

**Request Body:** same shape as POST (no client choice ids required; the service deletes previous choices and inserts the new set)

**Response:**

- Success (200): `{ "question": … }`
- Error (400): same validation as create
- Error (404): `"Question not found."`
- Error (500): unexpected server error

#### DELETE /api/questions/[id]

Deletes the question, its choices, and its attempts.

**Response:**

- Success (200): `{ "ok": true }`
- Error (404): `"Question not found."`
- Error (500): unexpected server error

#### GET /api/questions/[id]/preview

Returns the question for the preview page. Choice objects have `id`, `label`, and `position` only — no `isCorrect`.

**Response:**

- Success (200): `{ "question": { "id", "name", "question", "choices": [ { "id", "label", "position" } ] } }`
- Error (404): `"Question not found."`
- Error (500): unexpected server error

#### POST /api/attempts

Records one attempt and tells the client whether the selected choice is correct.

**Request Body:**

```json
{
  "questionId": "…",
  "choiceId": "…",
  "userId": "…"
}
```

`userId` is optional. When the client has a current user from login, send that id.

**Response:**

- Success (201):

```json
{
  "attempt": {
    "id": "…",
    "questionId": "…",
    "choiceId": "…",
    "userId": "…",
    "isCorrect": true,
    "createdAt": "…"
  },
  "message": "Correct. That is the right answer."
}
```

When incorrect, `isCorrect` is `false` and `message` is `"Incorrect. That is not the right answer."`

- Error (400): missing `questionId` or `choiceId`, or the choice does not belong to the question. Message describes the field error.
- Error (404): question or choice not found. Message: `"Question not found."` or `"Choice not found."`
- Error (500): unexpected server error

#### GET /api/attempts?questionId=

Lists attempts for one question.

**Response:**

- Success (200): `{ "attempts": [ { "id", "questionId", "choiceId", "userId", "isCorrect", "createdAt" } ] }`
- Error (400): missing `questionId`
- Error (500): unexpected server error

## Test-Driven Development

This feature is built with strict TDD. That is a process requirement, not a suggestion.

1. For each phase, write the behaviour tests **first**.
2. Run the tests and confirm they **fail** (red) because the behaviour does not exist yet.
3. Implement only enough production code to satisfy those tests.
4. Run the tests and confirm they **pass** (green).
5. Do **not** change, remove, skip, or weaken a test to make it pass. If implementation and a test disagree, fix the implementation.
6. Tests assert observable behaviour (status codes, response bodies, database side effects, what the user sees). They do not assert on internal implementation details such as private function names.
7. Never write assertions that cannot fail (`expect(true).toBe(true)`).
8. Each test must pass in isolation. Reset mocks in `beforeEach` with `vi.clearAllMocks()`.
9. Unit tests mock D1 and `getCloudflareContext()`. They must not reach a real database, network, or model provider.
10. Colocate tests: `src/lib/services/question.ts` is tested by `src/lib/services/question.test.ts`.

Follow `.cursor/skills/testing/SKILL.md` for Vitest, the `@/` alias, Cloudflare mocking, and React Testing Library conventions.

The Vitest harness already exists from the login sprint. Do not reinstall it.

## Risks and Mitigation

### Technical Risks

- **Risk**: Updating choices as a full replace can orphan attempts if a choice id is deleted while attempts still reference it.
- **Mitigation**: Attempts cascade when the parent question is deleted. For an in-place edit, delete previous choices only after the question still exists; if FK deletes fail because attempts reference old choice ids, delete those question’s attempts for the replaced choices in the same update, or delete-and-reinsert choices only when the service also deletes attempts that point at removed choice ids. Prefer: on update, delete attempts for that `question_id` that reference outgoing choice ids, then replace choices. Document this in implementation notes if the chosen order changes.

- **Risk**: Preview payload leaks the answer if it reuses the edit GET.
- **Mitigation**: Dedicated `/preview` endpoint that strips `isCorrect`. Tests must fail if the field is present.

- **Risk**: `getCloudflareContext()` does not work under jsdom.
- **Mitigation**: Mock `@opennextjs/cloudflare` and keep D1 behind `src/lib/`.

- **Risk**: Anonymous `?` placeholders bind incorrectly in local Wrangler.
- **Mitigation**: Use numbered placeholders (`?1`, `?2`) only.

- **Risk**: Agents weaken tests to get a green suite.
- **Mitigation**: Required test cases are listed in this PRD. Do not edit them down.

- **Risk**: Local `workerd` still crashes on this Windows machine, so migrate/preview/build may fail.
- **Mitigation**: Same as the login sprint. Unit tests mock D1. Do not apply `--remote` to work around it.

### User Experience Risks

- **Risk**: Refresh on `/test-bank` loses who is signed in; attempts may have a null `user_id`.
- **Mitigation**: Documented limitation. Do not add cookies in this phase.

- **Risk**: Teachers expect quizzes or a score history.
- **Mitigation**: This page is a question bank plus a single-question preview. Do not build a quiz runner.

- **Risk**: Accidental delete.
- **Mitigation**: Confirm in a dialog before `DELETE`.

## Troubleshooting Guide

Add entries here when bugs are found and fixed during implementation.

### Local D1 migrate / `cf-typegen` fail on Windows

**Problem**: `npx wrangler d1 migrations apply quiz-maker-db --local` crashes with a `workerd` access violation.
**Cause**: Wrangler starts the Workers runtime for that command.
**Solution**: Re-run after the VC++ Redistributable / workerd issue is fixed. Do not apply migrations with `--remote`. The migration file must still land in the repo.

### Preview shows which answer is correct before submit

**Problem**: The preview page or network response includes `isCorrect`.
**Cause**: Preview reused `GET /api/questions/[id]` or the UI read the edit payload.
**Solution**: Use `GET /api/questions/[id]/preview` only. Strip `isCorrect` in the route, not only in CSS.

### Foreign key errors on question update

**Problem**: Replacing choices fails because `attempts.choice_id` still points at old rows.
**Cause**: Full choice replace while attempts exist.
**Solution**: In `updateQuestion`, delete attempts for that question (or for the outgoing choice ids) before deleting old choices, then insert the new set.
